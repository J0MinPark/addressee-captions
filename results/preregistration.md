## 1. 시연 구성 선택 규칙 (dev에서만)

- **정확도 기준**: AI Hub 반합성 **dev**, 조건 **(single_mic, Y −6 dB, SNR 10 dB)**, 정답 정의 **"내 대화" = 라벨 x**(착용자와 같은 대화의 다른 참가자), 지표 **F0.5**.
  - 양성 = x, 음성 = y(옆 대화). 착용자 구간(w)과 unmatched(겹침 50% 미만)는 지표에서 뺀다.
  - 예측 양성 = 크게 표시(partner). 시나리오 12개를 합산한 정밀도·재현율로 F0.5를 계산한다.
- **제약 1**: 같은 조건에서 **자연 함정 오표시율이 timing 모드보다 낮다**(점추정).
  - 자연 함정 = 착용자 발화 종료 후 1.5초 안에 시작한 y 발화에 연결된 시스템 구간. 오표시율은 그중 크게 표시된 비율이다.
- **제약 2**: **원격 경로로 잰 자막 지연 p95 ≤ 2초**.
  - 사람이 Book5에서 `tools/latency_bench.py --remote`로 재서 준다("최종" 지연 = LLM 판정 반영까지).
  - 측정값이 없으면 서버 localhost 측정값으로 잠정 선택하고, **잠정**임을 결과 문서와 시작 로그 구성 이름 옆에 적는다.
  - 지연은 구성마다 다를 수 있으므로 LLM을 쓰는 구성과 쓰지 않는 구성을 각각 잰다(같은 판정기·같은 모델이면 같은 값으로 본다).
- **선택**: 두 제약을 만족하는 후보 중 F0.5 최대.
  - 동률(소수 셋째 자리까지 같음)이면 더 단순한 쪽을 고른다. 순서: timing 계열 < 손 가중치 < 학습된 융합, 플래그 적은 쪽.
  - 만족하는 후보가 없으면 **timing 모드를 배포**하고 시연 런북에서 함정 장면을 뺀다.
- **적용**: `tools/apply_selection.py`가 이 규칙의 결과(`results/demo_selection.json`)만 `app/demo_config.yaml`로 시연 프로필에 적용한다. 근거는 `results/demo_selection.md`에 남긴다.

## 3. 데이터 구성 (고정값)

- **라벨**: TL1–TL7(filekey 61634–61640), VL1(563185). **원천**은 Training 묶음 하나만 받는다.
  - 선택 규칙: 후보 세션 40개 이상인 묶음 중 원천 zip이 가장 작은 것. 없으면 후보가 가장 많은 묶음.
  - 라벨 TLn ↔ 원천 TSn이 같은 번호끼리 대응한다고 가정한다(받기 전에는 확인할 방법이 없다. 받은 뒤 파일명으로 확인해 보고한다).
- **후보 세션 필터**(`tools/aihub_select.py`):
  - speaker_num 3–4.
  - 다른 화자 구간이 0.3초 이상 겹치는 발화 비율 ≤ 20%.
  - 착용자로 쓸 화자가 10분 구간 안에서 발화 15회 이상.
  - 우선순위: media 독서토론 > 회의 > 온라인회의 > 토론 → relation "사회자 없이 토론자" → environment 태그 발화 비율이 낮은 순.
- **반합성 시나리오**(`tools/aihub_mix.py`, 시드 고정 20261002):
  - **X(내 대화)**: 한 세션의 10분 구간. 착용자 1명은 그 구간에서 발화가 가장 많은 화자.
  - **Y(옆 대화)**: 다른 세션의 10분 구간, 시작 오프셋 무작위.
  - 같은 세션은 X와 Y로 동시에 쓰지 않는다. dev와 test는 세션이 겹치지 않는다(`splits_aihub.json`).
  - **채널 B** = X + Y(X 대비 −6 dB, −10 dB) + DEMAND PCAFETER(SNR 10 dB, 5 dB). 레벨은 정답 발화 구간 RMS 기준.
  - **채널 A**: 착용자 발화를 원천 그대로(헤드셋 대용). oracle 조건만 쓴다. single_mic 조건은 B만 쓴다.
  - **라벨**: w = 착용자, x = X의 다른 참가자, y = Y의 발화. 시스템 구간은 시간 겹침이 가장 큰 발화에 연결한다. 겹침이 구간 길이의 50% 미만이면 unmatched로 빼고 개수를 보고한다.
  - **자연 함정**: 시나리오당 5개 미만이면 Y 오프셋을 다시 뽑는다(최대 5회). 그래도 미만이면 그대로 쓰고 보고한다.
  - 시나리오 수: **dev 12, test 12**.
  - 한국어 프로필: ASR ko, 한국어 판정 프롬프트, 호명 감지 끔, 위험 소리 끔(평가와 무관).
- **본인 발화 조건**:
  - oracle: 착용자 구간을 정답 시간으로 준다(판정 로직만 평가).
  - single_mic: 단일 마이크 모드. 착용자 등록 음성은 같은 세션의 평가 구간 밖에서 착용자 발화 10초를 가져온다.
- 조건 격자: 본인 발화 2 × Y 음량 2 × 소음 2 = **시나리오당 8조건**. 주 조건은 1절의 하나다.

## 4. 지표와 통계

- **지표**: 정밀도, 재현율, F0.5, 자막 오염도(크게 표시된 글자 중 y 비율), 자연 함정 오표시율, 옆 대화 화자 오등록률(Y 화자가 partner로 등록된 비율).
- **표**: Y 음량 × 소음 × 본인 발화 조건별 표.
- **통계**: 핵심 비교(timing vs 선택 구성, v1 vs 선택 구성)에 **세션 단위 부트스트랩 1000회** 95% 신뢰구간과 짝지은 차이(같은 재표본)를 붙인다.
- **절차**: dev 시나리오 1개로 끝까지 돌려 표가 나오는지 확인한 뒤 전체를 돌린다.

## 개정 1 (2026-10-02, AI Hub 결과를 만들기 전에 커밋)

**사유**: 일정상 원천 음성(TS 묶음 41GB 이상)을 받아 재생할 수 없다. 원천 zip은 받지 않는다.
**하지 않는 것**: 2절 원천 선택·추출, 3절의 오디오 혼합(채널 A/B, Y 음량, DEMAND 소음), 본인 발화 조건(oracle/single_mic).

**대체: AI Hub 라벨 기반 대화 시뮬레이션** (`tools/aihub_sim.py`)
- **라벨**: TL1–TL7, VL1(라벨링 데이터만). 세션 필터는 3절에서 오디오 관련 항목만 뺀 그대로다.
- **시나리오** = X 세션의 10분 구간 + Y 세션의 10분 구간(시작 오프셋 무작위). 두 발화 목록을 실제 시각 기준으로 합친다. 시드 20261002.
  - X: 착용자 1명, 그 구간에서 발화가 가장 많은 화자.
  - 각 발화를 하나의 구간으로 쓴다(정답 분할). 텍스트는 정제한 전사(form)다.
- **라벨**: w = 착용자, x = X의 다른 참가자(내 대화), y = Y의 발화(옆 대화).
- **화자 증거**: 화자 ID를 정답으로 쓴다. 같은 ID면 유사도 1, 다른 ID면 0이다. 등록·만료는 기존 정책 엔진이 처리한다.
- **의미 판정**: 한국어 판정 프롬프트(P1 수정판 포함)로 실제 Ollama(qwen3:4b)를 호출한다. P3 문맥은 합쳐진 흐름(옆 대화가 섞인)의 직전 발화로 만든다.
- **자연 함정**: 착용자 발화 종료 후 1.5초 안에 시작한 y 발화. 시나리오당 5개 미만이면 Y 오프셋을 다시 뽑는다(최대 5회).
- **분할과 수**: 세션 단위 dev/test(`splits_aihub.json`). 같은 세션은 X와 Y로 동시에 쓰지 않고, dev와 test 사이에서도 겹치지 않는다. **dev 24, test 24.**
- **정책**: 기존 오프라인 재시뮬레이션 경로(`tools/evaluate.py` simulate / `tools/tune_dev.py`)를 그대로 쓴다. 새 정책 로직은 만들지 않는다.

**시연 구성 규칙(1절) 변경**
- 정확도 기준: **AI Hub 라벨 기반 대화 시뮬레이션 dev 세트**, 정답 정의 "내 대화"(x), 지표 **F0.5**(시나리오 24개 합산). 오디오 조건이 없으므로 조건은 하나다.
- 제약 1(자연 함정 오표시율 < timing)과 제약 2(원격 자막 지연 p95 ≤ 2초, Book5 측정값이 없으면 localhost 값으로 잠정)는 그대로다. 선택·동률·대체(timing) 규칙도 그대로다.
- 후보 풀은 2절과 같다. 학습된 융합의 교차검증 단위는 (세션, 착용자)이고, 선택은 out-of-fold 점수로 한다.
- 통계: 세션 단위 부트스트랩 1000회, 핵심 비교에 짝지은 차이.
- 최종 시험: `tools/final_test_aihub_sim.py`, 잠금 `results/aihub_sim_final_test.lock`, 한 번만. 비교는 all, timing, v1, 선택 구성. 결과는 `results/aihub_sim_final_test.md`, `.csv`.

**이 시뮬레이션이 평가하지 않는 것**
- 받아쓰기 오류(정제한 정답 전사를 쓴다), 화자 임베딩 오류(정답 화자 ID), 구간 분할 오류(정답 발화 경계), 본인 발화 검출 오류(착용자 정답).
- 소음과 옆 대화 음량의 영향, 실시간 지연.
- 평가 대상은 판정 계층(타이밍, 화자 연속성, 의미 판정, 융합)뿐이다. 실제 시연 성능은 이보다 낮을 수 있다.

## 개정 2: AI Hub 평가 취소 (2026-10-02)

**사유**: AI Hub 데이터 이용 승인을 받을 수 없었다. API 다운로드가 "인증실패, 권한이 거부되었습니다"(HTTP 502)로 거부됐고, 공식 aihubshell로도 같은 결과였다. 발표 일정(2026-10-03 12:00) 안에 승인을 받을 수 없다.

**결과**
- P2(AI Hub 평가와 시연 구성 선택)와 P3(AI Hub 최종 시험)를 모두 취소한다(원 계획과 개정 1 모두). **AI Hub 데이터는 한 건도 받거나 처리하지 않았다.**
- 시연 구성은 **v1(P1c · 손 가중치)으로 확정**한다. `app/demo_config.yaml`은 만들지 않는다.
- AMI dev 선택 구성(P1-qwen3:4b-learned)은 **보고용으로만** 유지하고 `ami` 프로필에만 적용된다. 시연에는 쓰지 않는다.
- 1절의 선택 규칙과 제약은 적용되지 않았다(선택 대상 데이터 없음). 한국어 P1 버그 수정(`results/ko_prompt_fix.md`)은 AI Hub와 무관해 그대로 유지한다.
- 준비한 도구(`tools/aihub_download.py`, `aihub_select.py`, `aihub_sim.py`, `aihub_tune.py`, `final_test_aihub_sim.py`)는 남겨 둔다.
  실제 AI Hub 데이터로는 실행된 적이 없다(가짜 json으로 흐름만 점검했고, 그 출력은 저장소 밖 임시 폴더에 두었다가 지웠다).
